# คำอธิบายการทำงานของระบบ Receipt Chatbot

โค้ดนี้ถูกแบ่งออกเป็นหมวดหมู่หลักๆ เพื่อให้ง่ายต่อการจัดการและดูแลรักษา ดังนี้:

---

## 1. การตั้งค่าและจัดการ Path (Configuration & Paths)
**กลไก:** ส่วนนี้จะดึงค่าจากไฟล์ `.env` (เช่น API Key) และสร้างตัวแปรเก็บตำแหน่ง (Path) ของโฟลเดอร์ต่างๆ ที่ต้องใช้งาน เช่น โฟลเดอร์เก็บไฟล์ภาพ (uploads) โฟลเดอร์เก็บข้อมูล (data) และสร้าง FastAPI instance (`app`)

**สิ่งที่ถูกตั้งค่า:**
*   `OPENROUTER_API_KEY` และ `OPENROUTER_MODEL`: รหัสผ่านและชื่อโมเดล AI ที่จะใช้
*   `ALLOWED_EXTENSIONS`: กำหนดนามสกุลไฟล์ภาพที่อนุญาต (.jpg, .png)
*   คำสั่ง `mkdir`: สร้างโฟลเดอร์อัตโนมัติหากยังไม่มี

**ทำไมต้องมีมัน:** ป้องกันการฮาร์ดโค้ด (Hardcode) ข้อมูลความลับลงในโค้ดโดยตรง และทำให้แอปพลิเคชันรู้ว่าควรจะบันทึกไฟล์หรืออ่านไฟล์จากโฟลเดอร์ไหน ไม่ว่าจะรันในเครื่องไหนก็ตาม
**ความสัมพันธ์:** เป็นรากฐานสำคัญ โฟลเดอร์และค่าต่างๆ เหล่านี้จะถูกเรียกใช้ในทุกๆ ฟังก์ชันด้านล่าง (เช่น ตอนบันทึกรูป หรือตอนเรียก AI)

---

## 2. Utility: prompts (การจัดการคำสั่ง AI)
**กลไก:** ฟังก์ชัน `load_prompt(path)` ทำหน้าที่อ่านไฟล์ข้อความ (Text file) ที่ใช้สั่งการ AI

**ทำไมต้องมีมัน:** แทนที่จะเขียนคำสั่งยาวๆ ไว้ในโค้ด Python การแยกคำสั่ง (Prompt) ไปไว้ในไฟล์ `.txt` จะทำให้เราแก้ไขคำสั่งให้ AI ได้ง่ายขึ้น 
**ความสัมพันธ์:** สัมพันธ์โดยตรงกับส่วน API Chat ฟังก์ชันนี้จะถูกเรียกเพื่อดึงคำสั่ง (System Prompt) ไปแนบกับข้อความหรือรูปภาพของผู้ใช้ก่อนส่งให้ AI โดยการอ่านไฟล์ใหม่ทุกครั้ง ทำให้เราแก้ไฟล์ `.txt` แล้วระบบนำไปใช้ได้ทันทีโดยไม่ต้องรีสตาร์ทเซิร์ฟเวอร์

---

## 3. Utility: CSV (การจัดการฐานข้อมูล)
**กลไก:** ทำหน้าที่เป็น "ฐานข้อมูลอย่างง่าย" ประกอบด้วย 4 ฟังก์ชัน:
*   `ensure_csv()`: ตรวจสอบและสร้างไฟล์ CSV พร้อมหัวตาราง
*   `append_expense_row()`: เพิ่มข้อมูลใบเสร็จใหม่ลงไปต่อท้ายใน CSV
*   `read_expenses_sorted_desc()`: อ่านข้อมูลทั้งหมดแล้วเรียงลำดับจากล่าสุดไปเก่าสุด
*   `get_expenses_context()`: สรุปข้อมูลรายจ่ายทั้งหมดที่มี ออกมาเป็นข้อความ

**ทำไมต้องมีมัน:** เพื่อเก็บบันทึกข้อมูลอย่างถาวร (Persistent data) และเพื่อดึงข้อมูลประวัติการใช้จ่ายมาให้ระบบรู้
**ความสัมพันธ์:** 
*   `append_expense_row` จะถูกเรียกใช้เมื่อ AI อ่านใบเสร็จสำเร็จ
*   `get_expenses_context` จะถูกเรียกไปยัดใส่สมอง AI ตอนที่ผู้ใช้แชทถามคำถามทั่วไป เพื่อให้ AI ตอบคำถามเกี่ยวกับรายจ่ายที่ผ่านมาได้

---

## 4. Utility: normalize (การจัดระเบียบข้อมูลจาก AI)
**กลไก:** แปลงและทำความสะอาดสิ่งที่ AI ตอบกลับมาให้อยู่ในรูปแบบมาตรฐาน เช่น
*   `parse_receipt_json`: ดึงเฉพาะข้อมูล JSON ออกมาจากข้อความที่ AI ตอบ (เผื่อ AI ตอบน้ำท่วมทุ่ง)
*   `normalize_date`: แปลงปี พ.ศ. ให้เป็น ค.ศ. และจัด format เป็น DD/MM/YYYY
*   `normalize_amount`: ลบตัวอักษรหรือเครื่องหมาย (เช่น "฿", ",") ออกให้เหลือแค่ตัวเลขทศนิยม

**ทำไมต้องมีมัน:** AI มักจะตอบกลับมาในรูปแบบที่ไม่แน่นอน (เช่น บางทีตอบ 100 บางทีตอบ 100 บาท) การทำ Data Normalization ช่วยรับประกันว่าข้อมูลที่จะเซฟลง CSV จะสะอาดและนำไปคำนวณต่อได้จริง
**ความสัมพันธ์:** เป็นตัวกลาง (Middleware) ระหว่างคำตอบของ AI (ส่วนที่ 5) และการบันทึกลงฐานข้อมูล (ส่วนที่ 3)

---

## 5. Utility: เรียก OpenRouter (การเชื่อมต่อ API ภายนอก)
**กลไก:** ฟังก์ชัน `call_openrouter` ทำหน้าที่นำข้อความหรือรูปภาพ ส่งผ่าน HTTP Post Request ไปยังเซิร์ฟเวอร์ของ OpenRouter (ผู้ให้บริการ AI)

**ทำไมต้องมีมัน:** เป็นสมองของระบบ โค้ดของเราเองไม่ได้มีความสามารถในการอ่านภาพหรือคิดวิเคราะห์ จึงต้องส่งข้อมูลไปให้ AI ภายนอกช่วยจัดการ
**ความสัมพันธ์:** ดึง API Key จากส่วนที่ 1 และถูกเรียกใช้งานอย่างหนักในส่วนที่ 7 (Routes API)

---

## 6. Routes: หน้าเว็บ (หน้าต่างแสดงผล)
**กลไก:** ฟังก์ชัน `index()` เมื่อมีคนเข้าสู่ URL หลัก (`/`) ระบบจะส่งไฟล์ `index.html` ไปแสดงผลบนเบราว์เซอร์

**ทำไมต้องมีมัน:** เป็นส่วนติดต่อผู้ใช้ (Frontend) ให้ผู้ใช้มีปุ่มกด มีหน้าต่างแชท เพื่อใช้งานระบบ

---

## 7. Routes: API (หัวใจหลักของแอปพลิเคชัน)
**กลไก:** แบ่งเป็น 2 API หลัก:
1.  `/api/expenses`: ส่งข้อมูลรายจ่ายทั้งหมดจาก CSV ไปให้หน้าเว็บแสดงผลเป็นตาราง
2.  `/api/chat`: **นี่คือฟังก์ชันที่ซับซ้อนที่สุด** จะแยกการทำงานเป็น 2 โหมด:
    *   **โหมดถามตอบทั่วไป (ไม่มีรูป):** ดึงประวัติรายจ่าย (`get_expenses_context`) + คำสั่ง (`load_prompt`) ส่งให้ AI ตอบ
    *   **โหมดอ่านใบเสร็จ (มีรูป):** 
        1. ตรวจสอบนามสกุลไฟล์
        2. บันทึกรูปภาพลงโฟลเดอร์
        3. แปลงรูปเป็น Base64 แล้วส่งให้ AI อ่าน
        4. ใช้ `parse_receipt_json` แยกข้อมูลที่ AI ตอบ
        5. *มีกลไก Retry:* ถ้า AI ไม่ยอมตอบเป็น JSON จะมีการส่งคำสั่งไปด่า/ย้ำเตือนให้ AI ตอบเป็น JSON ใหม่ 1 ครั้ง
        6. จัดระเบียบข้อมูล (Normalize) และเซฟลง CSV

**ทำไมต้องมีมัน:** เพื่อเป็นศูนย์กลางรับเรื่องจากผู้ใช้ (Frontend) แจกจ่ายงานให้ฟังก์ชันต่างๆ (ดึงคำสั่ง, เรียก AI, จัดรูปแบบข้อมูล) และส่งผลลัพธ์กลับไปให้ผู้ใช้
**ความสัมพันธ์:** เป็นตัวผูก (Orchestrator) ทุกส่วน (ตั้งแต่ส่วน 1 ถึง 5) เข้าด้วยกันเพื่อทำงานให้สำเร็จ

---

## 8. การรันเซิร์ฟเวอร์
**กลไก:** `uvicorn.run("main:app", ...)`
**ทำไมต้องมีมัน:** เป็นคำสั่งสำหรับเปิดเซิร์ฟเวอร์ให้ทำงานและรอรับ Request ตลอดเวลา หากไม่มีส่วนนี้ โค้ดจะไม่ถูกรันขึ้นมาเป็นเว็บไซต์
